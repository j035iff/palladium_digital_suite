# UI & Wireframe Specifications

> **Implementation status:** Live sheet Persistent Core order is **Identity summary (top) → tool strip (Identity · Stats · Bonuses · Skills · Abilities · Gear → optional Become Morphus after Gear when dual-form · middle **TABLE** status / **Join table** · quick-ref HP/SDC/PPE/(ISP) · XP/level) → Campaigns | Combat mode switch → mode body** (`MainLayout`, `LiveSheetChromeStrip`, `LiveSheetTabBody`). Chrome label **Campaigns** (internal mode id stays `story`). Selecting a strip tab opens an **overlay** of that tab’s existing panel via `LiveSheetTabOverlay` → `LiveSheetTabBody` (one pipeline — mock Stats+Campaigns-together was screenshot artifact). Dual-form overlays include a shared **Facade | Morphus** toggle next to Close (same active-form pipeline as strip Become Morphus). Overlay headers also page prev/next strip tabs with labeled destination arrows flanking Close (wrap Identity ↔ Gear). Mode switch clears the overlay and shows that mode’s Home (no Home pill under the switch). **TABLE** (strip center): when seated shows the campaign/table name; when not, **Join table** opens `SheetJoinTableDrawer` + `JoinTablePanel` (shared session client / `party.snapshot` — no launcher Join / no `join_table` viewport). Peer-visible player display name uses `JOIN_PLAYER_NAME_PLACEHOLDER` until launch sign-in. **Campaigns Home** persists forever campaign tabs on the character save (`sheetCampaigns`), keyed by **normalized table/campaign name** — join reuses an existing tab when the name matches; a different name creates a new tab. Pills sort **left→right by that character’s** `lastAtTableMs` (most recent / currently seated first; oldest last) — order is per character save, never global/device-wide. The seated table’s campaign pill is **green**. Each campaign has its own **People · Places · Things · Notes** wiki journal (shared `[[kind:id|label]]` model via `ContentLinkedNotesField`; content never syncs to Hub). **Delete** / **Merge** on the seated campaign are greyed with tooltip; other campaigns stay deletable and can merge into the current-table campaign. Legacy global `playNotes` may seed the first campaign’s notes only. **Combat Home** renders `CombatHUD` `layout="panel"` with a slim sticky APM + Initiative + Melee chrome (outside scroll) and Campaigns-style sub-tabs **Vitals | Physical | Abilities** (`liveCombatTabs`; tab body scrolls): Vitals = drag-reorderable damage pools L→R (shields→armor→S.D.C.→H.P.; M.D.C. replaces S.D.C.+H.P.; Natural A.R. on S.D.C./H.P.; Apply Damage/Heal + direct-to-HP; armor Expand); Physical = Unarmed/Ancient/Modern bubbles (Unarmed label = active Hand-to-Hand style); Abilities = P.P.E./I.S.P. + placeholder. No H.F. or Perception chips on Combat. Strip quick-ref vitals stay visible above. Full identity detail opens only on the **Identity** strip overlay (`LiveIdentityPanel` / `IdentityHeader` details) — no Expand/Minimize under the header; the unexpanded Identity summary strip stays anchored. Identity tab edits **all** identity/profile fields (Name, Alignment, Sex, Age, Height, Weight, Eyes, Hair, **Description**, **Personality**, **Character Image**) — **Race** and **O.C.C.** stay read-only; Height/Weight follow **Standard / Metric** units preference; **Aliases** CRUD lives on the same tab; Description / Personality are freeform player text on `identityProfile` (not catalog); Character Image uses a Familiar Surface device file picker (`identityProfile.portraits`, jpeg/png/webp resized for local save) — non–dual-form one **Character Image**; Nightbane independent **Facade Image** + **Morphus Image** (both editable; `resolveActivePortrait` for active-form display). When joined, Identity tab lists other seated players with per-peer **Show my image to…** On/Off (default Off; `portraitShareAllowCharacterIds`, Save-gated). Campaigns → People shows At-this-table peer thumbnails only when allowlisted. Dual-form **Become Morphus / Become Facade** sits in the strip **after Gear** (omitted with no gap when the character is not dual-form — Pillar 6). Join picks a **Name at the table** (default = real name) that peers see while the GM keeps the canonical name. Live-sheet edits stay **dirty until explicit Save** (orange Save when dirty; greyed/disabled when clean). **Abilities** nests **Natural · O.C.C. · Magic · Psionics · Talents**; empty categories are omitted. Cast / duration / pump workflow and toast/tap-to-expand attributes remain **target UX**.

This document defines the layout, visual hierarchy, and interaction design for the Palladium Digital Suite character sheet. It adheres to the Visual Continuity, Intuitive Depth, and Familiar Surface pillars: the frame stays anchored, deep math stays one tap away, and controls stay as simple and conventional as the task allows so the player never has to understand internal systems, ids, or engine terms.
1. The Persistent Core (Anchored Elements)
These elements are "anchored" to specific screen coordinates and do not move when switching between Campaigns and Combat modes. This provides a consistent frame of reference for the player.
A. Identity Header (Absolute Top)
Identity Row: One-line summary containing Name, Race, O.C.C., and Alignment (name editable inline) — no **IDENTITY** eyebrow above the name. Summary strip stays anchored — no Expand/Minimize.
**Identity overlay tab** (first strip pill, left of Stats — `LiveIdentityPanel`): **all** profile fields — Sex, **Apparent age**, Height, Weight, Eyes, Hair, Alignment select — plus **Aliases** (add / rename / remove) and freeform **Description** / **Personality** textareas. Height/Weight labels and inputs follow Settings → Units (Standard: Ft./In. + lbs; Metric: **cm** + kg — height is whole centimeters only, never meters) via `identityMeasures` + shared units convert helpers. **Shared across forms:** Name, Race, O.C.C. **Nightbane per-form** (active form drives the tab): sex, apparent age, height/weight, eyes/hair, aliases, description/personality, alignment, image — Morphus unset anthropometrics fall back to Facade (`identityProfile.morphus` overlay); **description / personality / image are fully independent** and swap with Become Morphus / Become Facade (no prose fallback). Morphus trait height/weight mods auto-apply with source notes; dice trait mods show fill-in callouts (never spawn-block). **Race** and **O.C.C.** remain read-only (and are **not** duplicated at the top of the Identity overlay — only the **Alignment** dropdown stays there for editing). Tab composition: **left** stacked traits + Aliases + genre stamp, **center** form-labeled Description / Personality, **right** active-form Character Image (`identityProfile.portraits.primary` or `.morphus` — one slot that swaps with form, not both stacked). Character Image window default is **≥2×** the prior ~176×160 slot (~352×320 CSS px); **corner-drag** resizes within min/max; new file picks **aspect-fit** the window (`identityProfile.portraitWindows`, Save-gated). When viewing Morphus, **Morphus traits** (creation picks via `buildLiveMorphusIdentityTraitBreakdown`) open as a **popover from the Morphus description box header** (Familiar Surface — header is the affordance; no static traits column). Morphus **Stance** (when available) may still appear on this tab; **Surface** and **Natural A.R.** chrome are not shown here. When joined, **Show my image to…** per-peer On/Off (default Off; `portraitShareAllowCharacterIds`). Peers see the joiner’s `presentedForm` identity (portrait + projected name from that form’s alias list). Full identity detail is **only** on this overlay — not duplicated on Campaigns/Combat Home. Settings gear stays in the header utility cluster with Save / Portal.
**Save chrome (Persistent Core):** Explicit **Save** button beside Portal — **orange and enabled** when the character is dirty; **greyed and disabled** when clean (no separate Saved/Unsaved chip — the button alone carries state). Edits (identity, notes, gear, vitality, XP, etc.) do **not** write the character file until Save. While joined at a table, the same gate applies to peer-facing `party.snapshot` (identity / projected name / other dirty sheet fields stay local until Save). Leaving the sheet via Portal (including join-table leave) with Unsaved edits opens a dialog: **Save** or **Continue without saving** (plus Stay on sheet). One dirty/save pipeline for Campaigns and Combat — no mode fork (`src/lib/liveSheetSave.ts`).
Join Table projection: in-sheet Join drawer — player picks **Name at the table** (real name default, or an alias, or **Add alias** via dialog). Peer-visible **player** display name is `JOIN_PLAYER_NAME_PLACEHOLDER` until launch sign-in. Peers see projected character name on **At this table** (`seat.projectedCharacterName`); GM Hub keeps real `character.name`. Changing the projected name (or other identity) on the live sheet after join stays Unsaved until **Save**, which refreshes the seated snapshot.
B. Tool strip (below Identity)
Forge-style pills (`src/lib/liveSheetTabs.ts` → `buildLiveSheetOverlayTabViews`, `ForgeNavigationBar`) — **Identity · Stats · Bonuses · Skills · Abilities · Gear** then optional **Become Morphus / Become Facade** immediately after Gear when `supportsDualForm` (omitted with no empty slot otherwise — Visual Continuity). Center **TABLE** field: seated → campaign/table name; not seated → **Join table** opens `SheetJoinTableDrawer`. Selecting a strip pill opens an overlay of that tab’s content (`LiveSheetTabOverlay` + `LiveSheetTabBody`); selecting again or Close / Escape dismisses. Dual-form overlays show a shared **Facade | Morphus** toggle next to **Close** (same `toggleForm` / `presentedForm` pipeline as strip Become Morphus; omitted when not dual-form). Prev/next buttons flank Close and jump to the adjacent strip overlay (`adjacentLiveSheetOverlayTab`, wrap-around); labels show the destination tab (e.g. ← IDENTITY / BONUSES →). Quick-reference pools sit in a filled chrome chip (HP / SDC / PPE / ISP when relevant). Experience chip: Level + XP → next threshold (`IdentityXpBar`).
C. Mode switch
Sticky **Campaigns | Combat** pill pair (`liveSheetModeLabel`; internal ids `story` | `combat`). No Home pill under the pair — mode Home is simply the Campaigns / Combat body when no strip overlay is open. Mode changes clear any open overlay and show that mode’s Home. Campaigns Notes use the shared wiki editor with a light **sheet** surface (`ContentLinkedNotesField` `surface="sheet"`) — wiki behavior shared with Hub; player journal content is not synced.
Bonuses overlay (`bonuses` → `SavingThrowsPanel` / `buildLiveBonusesOverlay`; **active form only**): **BONUSES** (black-outline cards) — Perception · Trust/Intimidate · Charm/Impress · Base Skill % · Base ME · Base PS Damage · Base PP · Base PE from exceptional / attribute engines. **SAVING THROWS** (blue-outline cards) — exactly the mock fixed 10 (Magic with Spell/Ritual targets, Horror Factor, Poisons/Toxins, Disease **14+**, Coma/Death %, Psionics, Illusions, Insanity, Possession, Mind Control); dynamic third row for extras — **Nightbane always leads with Save vs Becoming** (row shows even if Becoming is alone); other extras after it; non-Nightbane row **hidden until at least one extra exists**. Bonus number is most prominent; no bonus / +0 → black **—**; penalty → red; engine immunity wording as-is (**Immune** / **Impervious**); book/engine TNs as footnotes when in SoT; situational HF / Coma/Death print **varies**; Illusions / Possession omit a bottom TN until SoT has one. HF card is **save bonus only** (aura stays on CombatHUD). Hover tooltips clamp/flip inside the overlay (no spill off the ends). See `combat_logic.md` §4.
Abilities nests **Natural / O.C.C. / Magic / Psionics / Talents**; empty categories are omitted.
2. The Active Zone: State 1 (Campaigns)
Campaigns **Home** (`CampaignsHome`): forever campaign pills on `character.sheetCampaigns`, named by table/`campaignName` on join (`liveSheetCampaigns.ts`). Same normalized name → reuse tab; different name → new tab. Join/rejoin stamps `lastAtTableMs` on that character’s campaign row; pills sort left→right by that stamp (most recent / seated first; oldest last) — Character A’s order is independent of Character B’s. Seated table’s pill is **green**. Sub-tabs **People · Places · Things · Notes** are **per-campaign** wiki journals sharing GM Hub’s content-link model (`ContentLinkedNotesField` + `contentLinks` / placeholders). **Delete campaign** / **Merge…** live on the PPTN navy bar; when the selected campaign is the seated table, both are greyed with tooltip (`CAMPAIGN_AT_TABLE_LOCK_TOOLTIP`). Other campaigns remain deletable; other campaigns may still merge **into** the current-table campaign. Shared strip overlays **Identity / Stats / Bonuses / Skills / Abilities / Gear** reuse the same `LiveSheetTabBody` panels.
A. The Attribute Grid (2x4 Layout)
A structured grid for the 8 primary attributes (I.Q., M.E., M.A., P.S., P.P., P.E., P.B., Spd).
Numbers highlight in Green/Red if "Current Value" differs from "Base Value."
Tap-to-Expand: Shows the specific bonuses provided by that attribute (e.g., P.P. 20 shows +3 to Strike/Parry/Dodge).

B. Physical Feats & Socials Panel
Movement Hub: Displays ground, swim, and fly speed (MPH and Yards per Melee per `docs/movement_engine_spec.md`). Also includes calculated leaping distances (standing/running, horizontal/vertical).
Social Dashboard: Percentages for Trust/Intimidate (M.A. based) and Charm/Impress (P.B. based).
Lifting/Carrying: Max weight capacities based on P.S. and P.E.
3. The Active Zone: State 2 (Combat / Action)
Triggered via the **Combat mode** switch, this state opens Combat Home and shows tactical data while keeping Identity + tool strip + mode switch anchored.
A. Combat category bubbles
The Unarmed bubble **label** is the active Hand-to-Hand style (`Hand to Hand: EXPERT`, `NONE`, …). **Initiative** sits in the APM header (hover math). Three category bubbles — Unarmed (HtH name) / **Ancient Weapon** / **Modern Weapon** — show collapsed strike/parry/damage for the currently selected item. Empty weapon bubbles stay visible and **grayed** with a Gear-tab explanation (never hidden). A carried firearm still fills Modern even when the host genre has no modern W.P. rows (e.g. a Nightbane **rifted** into Palladium Fantasy) — the slot stays usable, with a short “brought from another world” note. Simple W.P. glyphs (fist / sword / rifle / whip / …) identify type — not a looter-shooter art pack.
**Expand** (one bubble at a time): Unarmed shows remaining combat-sheet totals (not Initiative), punch/kick/specials, dice, and a style picker when the character owns more than one HtH skill (Combat only — Skills has no HtH UI). Weapon expands include a picker of all carried Gear weapons of that era plus the full strike card (modes, ammo, traits, dice). Bonus-breakdown hover/focus tips on those expand tiles (and Initiative) render via the shared clamped overlay tooltip layer — not clipped by the bubble’s rounded `overflow: hidden` shell.
B. APM & Hand-to-Hand Tracker
APM Tracker: Remaining pips are tappable. Each tap spends **1** A.P.M. (left → right). Spent pips are not toggles — **New melee round** is the only refill. Multi-cost maneuvers (untrained Hand-to-Hand, power punch) = one tap per action. Implementation: `CombatHUD` `ApmPipRow`.
Hand-to-Hand Dashboard: style name replaces the Unarmed bubble title; punch/kick/specials live in the Unarmed expand. **No Hand-to-Hand UI on Skills** — Combat only (Joe 2026-10-13); styles stay out of percentile `SkillList` rows.
**Skills overlay** (`skills` → `SkillList` via `buildLiveSkillSections` / `filterLiveSkillSections`): sheet skills group by **selection category** when recorded (`SheetSkill.selectionCategory` from creation browse — e.g. Prowl under Rogue vs Physical), else catalog primary via `catalogSkillId` (creation instance ids alone must not dump into Other). **Language** and **Literacy** pin to a top Familiar Surface section **Language & Literacy** (catalog book category remains Technical for creation). Hand-to-Hand styles are **omitted** from the Skills overlay entirely (Combat Unarmed). **Familiar Surface filters** above the list: category dropdown (All + categories present on this character) and name search; both combine with AND when set; empty match shows an explicit “no skills match” state. **Sub-skill %** tracks from catalog `subTasks[]` / `subSkills[]` nest under the parent in **one skill box** as indented `⇨ (Sub)` lines (e.g. Acrobatics → `(Sense of balance)`), each with its own % / tooltip / description; when the parent also has a scalar root `%` (e.g. Climbing), the parent line keeps its % beside nested `(Rappelling)`. **Acrobatics/Gymnastics overlap** (`skills/utils/skill_global_rules.json`): attribute/combat bonuses stack; duplicated sub-abilities keep the **best** % (winner); loser shows a **black dash** with hover/focus tooltip **See {OtherParent}** (no second %); grant-only Climbing/Prowl show **Provided by …: does not increase per level** as a tooltip on the provided % until taken separately. Stats-only physical training — catalog rows with `hasPhysicalTrainingProgression` / no self % (Boxing, Running, Athletics (general), etc.) — land in their own **Physical** section pinned at the **bottom** after other categories. **Dual-nature** skills (sub-% **and** `physicalSkillBonuses`, e.g. Acrobatics / Gymnastics) also appear in that bottom Physical bucket with bonus summary. Percentile Physical skills (Climbing, Swimming, …) stay under **Physical** in normal category order. **Percentile rows** show the skill **% on the closed list** (default **blue**; **green/red** when Temporary net is positive/negative); **hover/focus the %** opens a Bonuses-style fixed tooltip with non-zero source portions in Joe order **Base → IQ → OCC/RCC (or OCC Related / RCC Related) → Synergies → Other → Level → Temporary** (`buildLiveSkillPercentDetail` / `resolveLiveSkillOccBonusPortion`; bonuses green, penalties red); **click the skill name** expands **Description** only (catalog text or placeholder — book write-ups still need ingest; see `docs/ingest/skills.md`). Temporary ability→skill % duration casts are not fully wired yet (`sn_abilities_selection.md`); when runtime status/temporary lines exist they appear last and tint the list %. **Stats-only Physical** show bonus/summary on the closed row — **no list % / fake d100**. **Weapon proficiencies** (`isWeaponProficiencySheetSkill`) show the **proficiency name only** in the skill box — no %, no bonus/summary text (Joe 2026-10-12 / 2026-10-13); description on expand.

**Current Combat Home:** `CombatHUD` `layout="panel"` — slim sticky tap-to-spend APM + Initiative + Melee chrome (outside scroll; height capped to pips/Melee), Campaigns-style sub-tabs **Vitals | Physical | Abilities** beneath, scroll only inside the active tab body. **Vitals:** absorb-order damage pool cards (default shields → armor → S.D.C. → H.P.; drag-reorder; engine L→R; M.D.C. single pool when applicable; Natural A.R. on S.D.C. and H.P.; Apply Damage/Heal + direct to hit points; armor Expand = stats + special features). **Physical:** Unarmed (HtH name) / Ancient / Modern bubbles + narrative log. **Abilities:** P.P.E. / I.S.P. at top; cast body placeholder. H.F. and Perception removed from Combat. Strip quick-ref stays visible above. One-tap ready-weapon icon strip is still later polish.
4. Visual Transition & Continuity Rules
Anchoring: Identity summary, tool strip, and mode switch stay fixed relative to each other when swapping Campaigns ↔ Combat; full identity detail opens as the Identity overlay (does not push the strip down).
The "Toast" System: Temporary changes (e.g., gaining +2 P.S. from a spell) appear as floating text "toasts" over the affected stat before fading.
Logic Transparency: Any calculated number can be tapped to reveal the underlying math (Attribute + Skill + Bonus).
