# UI & Wireframe Specifications

> **Implementation status:** Live sheet Persistent Core order is **Identity (top) → tool strip (Stats · Saves · Skills · Abilities · Gear + quick-ref HP/SDC/PPE/(ISP) + XP/level) → Campaigns | Combat mode switch → mode body** (`MainLayout`, `LiveSheetChromeStrip`, `LiveSheetTabBody`). Chrome label **Campaigns** (internal mode id stays `story`). Selecting a strip tab opens an **overlay** of that tab’s existing panel via `LiveSheetTabOverlay` → `LiveSheetTabBody` (one pipeline). Mode switch clears the overlay and shows that mode’s Home. **Campaigns Home** shows campaign pills (table/`campaignName` from join + device-local join memory) and sub-tabs **People · Places · Things · Notes** — Notes reuse character `playNotes`; PPTN others are empty-state stubs (no GM Hub wiki fork). **Combat Home** renders `CombatHUD` `layout="panel"` with vitals cards + A.R./H.F./Perception, APM + Initiative + Melee refresh, Unarmed/Ancient/Modern bubbles (Unarmed label = active Hand-to-Hand style). Identity Expand pushes the strip and everything below down. Identity Expand edits **all** identity/profile fields (Name, Alignment, Sex, Age, Height, Weight, Eyes, Hair) — **Race** and **O.C.C.** stay read-only; Height/Weight follow **Standard / Metric** units preference (ft/in+lbs vs **cm**+kg; canonical persist stays US Customary); **Aliases** CRUD lives on the same expand; Join Table picks a **Name at the table** (default = real name) that peers see while the GM keeps the canonical name. Live-sheet edits stay **dirty until explicit Save** (Saved/Unsaved indicator + Save button on the Persistent Core next to Portal) — file persist **and** joined-table `party.snapshot` both wait for Save; leaving via Portal with unsaved edits opens a Save / Continue without saving dialog (join-table leave included). **Abilities** nests **Natural · O.C.C. · Magic · Psionics · Talents**; empty categories are omitted. Cast / duration / pump workflow remains **target UX**. Toast system and tap-to-expand attributes remain **target UX**. Full PPTN wiki linking and Description/Personality/Image depth remain **out of pass 1**.

This document defines the layout, visual hierarchy, and interaction design for the Palladium Digital Suite character sheet. It adheres to the Visual Continuity, Intuitive Depth, and Familiar Surface pillars: the frame stays anchored, deep math stays one tap away, and controls stay as simple and conventional as the task allows so the player never has to understand internal systems, ids, or engine terms.
1. The Persistent Core (Anchored Elements)
These elements are "anchored" to specific screen coordinates and do not move when switching between Campaigns and Combat modes. This provides a consistent frame of reference for the player.
A. Identity Header (Absolute Top)
Identity Row: One-line summary containing Name, Race, O.C.C., and Alignment (name editable inline).
Profile Expand (Expand/Minimize — not a separate overlay): **all** profile fields — Sex, Age, Height, Weight, Eyes, Hair, Alignment select — plus **Aliases** (add / rename / remove). Height/Weight labels and inputs follow Settings → Units (Standard: Ft./In. + lbs; Metric: **cm** + kg — height is whole centimeters only, never meters) via `identityMeasures` + shared units convert helpers. **Race** and **O.C.C.** remain read-only labels. Character Description / Personality / Image remain **target UX** (placeholders in mockups; not on the identity model yet). Expanding Identity **pushes** the tool strip and mode body down (Visual Continuity — not a floating overlay).
**Save chrome (Persistent Core):** Explicit **Save** button with a Saved / Unsaved status dot beside Portal. Edits (identity, notes, gear, vitality, XP, etc.) do **not** write the character file until Save. While joined at a table, the same gate applies to peer-facing `party.snapshot` (identity / projected name / other dirty sheet fields stay local until Save). Leaving the sheet via Portal (including join-table leave) with Unsaved edits opens a dialog: **Save** or **Continue without saving** (plus Stay on sheet). One dirty/save pipeline for Campaigns and Combat — no mode fork (`src/lib/liveSheetSave.ts`).
Join Table projection: on Join Session the player picks **Name at the table** (real name default, or an alias, or **Add alias** via dialog → **Enter table with alias** / **Cancel** back to the join screen). Peers see that projected name on the joined-sheet **At this table** roster (`seat.projectedCharacterName`); GM Hub At-the-table / history / Players overlay keep the real `character.name`. Changing the projected name (or other identity) on the live sheet after join stays Unsaved until **Save**, which refreshes the seated snapshot.
B. Tool strip (below Identity)
Forge-style pills (`src/lib/liveSheetTabs.ts` → `buildLiveSheetOverlayTabViews`, `ForgeNavigationBar`) — **Stats · Saves · Skills · Abilities · Gear** (no Home pill on the strip). Selecting a pill opens an overlay of that tab’s content (`LiveSheetTabOverlay` + `LiveSheetTabBody`); selecting again or Close / Escape dismisses. Quick-reference pools: HP / SDC / PPE / (ISP when relevant). Experience chip: Level + XP → next threshold (`IdentityXpBar`).
C. Mode switch
Sticky **Campaigns | Combat** (`liveSheetModeLabel`; internal ids `story` | `combat`). Mode changes clear any open overlay and show that mode’s Home.
Saving Throws panel: Standard saves show **vs N** (GM-called base target) and **(+bonus)** to add to d20; hover reveals full breakdown. A separate **attribute-only saves** block covers P.E./M.E. exceptional rows and Save vs Becoming. Horror Factor is a dedicated aura block. Implementation: `SavingThrowsPanel.tsx` — see `combat_logic.md` §4. On the live sheet, Saves opens via the strip overlay (`saves`).
Abilities nests **Natural / O.C.C. / Magic / Psionics / Talents**; empty categories are omitted.
2. The Active Zone: State 1 (Campaigns)
Campaigns **Home** (`CampaignsHome`): campaign pills named by table/`campaignName` when the character joins (multiple joins → multiple pills via device-local join memory in `liveSheetCampaigns.ts` — not GM Hub storage). Sub-tabs **People · Places · Things · Notes**. Notes = persistent freeform `playNotes`. People/Places/Things = Radical Visibility empty states until coordinated with GM Hub. Shared strip overlays **Stats / Saves / Skills / Abilities / Gear** reuse the same `LiveSheetTabBody` panels.
A. The Attribute Grid (2x4 Layout)
A structured grid for the 8 primary attributes (I.Q., M.E., M.A., P.S., P.P., P.E., P.B., Spd).
Numbers highlight in Green/Red if "Current Value" differs from "Base Value."
Tap-to-Expand: Shows the specific bonuses provided by that attribute (e.g., P.P. 20 shows +3 to Strike/Parry/Dodge).

B. Physical Feats & Socials Panel
Movement Hub: Displays ground, swim, and fly speed (MPH and Yards per Melee per `docs/movement_engine_spec.md`). Also includes calculated leaping distances (standing/running, horizontal/vertical).
Social Dashboard: Percentages for Trust/Intimidate (M.A. based) and Charm/Impress (P.B. based).
Lifting/Carrying: Max weight capacities based on P.S. and P.E.
3. The Active Zone: State 2 (Combat / Action)
Triggered via the **Combat mode** switch, this state opens Combat Home and shows tactical data while keeping Identity + tool strip + mode switch anchored.
A. Combat category bubbles
The Unarmed bubble **label** is the active Hand-to-Hand style (`Hand to Hand: EXPERT`, `NONE`, …). **Initiative** sits in the APM header (hover math). Three category bubbles — Unarmed (HtH name) / **Ancient Weapon** / **Modern Weapon** — show collapsed strike/parry/damage for the currently selected item. Empty weapon bubbles stay visible and **grayed** with a Gear-tab explanation (never hidden). A carried firearm still fills Modern even when the host genre has no modern W.P. rows (e.g. a Nightbane **rifted** into Palladium Fantasy) — the slot stays usable, with a short “brought from another world” note. Simple W.P. glyphs (fist / sword / rifle / whip / …) identify type — not a looter-shooter art pack.
**Expand** (one bubble at a time): Unarmed shows remaining combat-sheet totals (not Initiative), punch/kick/specials, dice, and a style picker when the character owns more than one HtH skill (same list as the Skills tab). Weapon expands include a picker of all carried Gear weapons of that era plus the full strike card (modes, ammo, traits, dice).
B. APM & Hand-to-Hand Tracker
APM Tracker: Remaining pips are tappable. Each tap spends **1** A.P.M. (left → right). Spent pips are not toggles — **New melee round** is the only refill. Multi-cost maneuvers (untrained Hand-to-Hand, power punch) = one tap per action. Implementation: `CombatHUD` `ApmPipRow`.
Hand-to-Hand Dashboard: style name replaces the Unarmed bubble title; punch/kick/specials live in the Unarmed expand. Owned styles also list on the **Skills** tab (not as percentile `SkillList` rows).

**Current Combat Home:** `CombatHUD` `layout="panel"` — vitals cards (HP/SDC/PPE/(ISP)) + A.R./H.F./Perception, tap-to-spend APM + Initiative + Melee refresh, Unarmed (HtH name) / Ancient / Modern bubbles, apply damage/heal, narrative log. Strip quick-ref stays visible above. One-tap ready-weapon icon strip is still later polish.
4. Visual Transition & Continuity Rules
Anchoring: Identity, tool strip, and mode switch stay fixed relative to each other when swapping Campaigns ↔ Combat; Identity Expand only grows downward.
The "Toast" System: Temporary changes (e.g., gaining +2 P.S. from a spell) appear as floating text "toasts" over the affected stat before fading.
Logic Transparency: Any calculated number can be tapped to reveal the underlying math (Attribute + Skill + Bonus).
